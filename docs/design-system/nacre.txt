Brand book
Nacre is the visual language of Kushwant KR's portfolio: a deep lagoon, one iridescent pearl,
and type from an Indian foundry. Hyderabad is the City of Pearls, and a pearl grows layer by
layer, the way an engineer does. Keep everything quiet so the pearl stays the one
memorable thing.

Principles
 1. The pearl is the only ornament. The 3D pearl in the hero, the headline's full stop, the KR
    monogram's dot, and the Pearl chat launcher are one object at four sizes. Nothing else
    glows, floats, or carries a gradient.
 2. Round means press. Use radius-pill and circles only for things a visitor presses:
    buttons, chips, the launcher, the send button. Things you read or fill in use radius-sm to
     radius-lg .
 3. Layers, not cards. Content sits on tonal layers: lagoon , then reef , then shoal . Give
    an element a fill or an outline only when it is a separate object, such as a case study you can
    open.
 4. Evidence looks like evidence. Dates, metrics, and links get one treatment everywhere:
    tabular figures, numbers in pearl , links in rose with an underline.
 5. Motion answers people. Two things move unprompted: the hero's opening, where the pearl
    grows out of the full stop, and the particles responding to scroll. Everything else moves only
    when a visitor acts.

Colour
   Set the page and the 3D canvas on lagoon . Use reef for case-study cards, form fields,
   code blocks, and the chat panel; use shoal for hover states, visitor chat bubbles, menus,
   and toasts.
   Set text in pearl and secondary text in mist . Both reach 5.2:1 or more on lagoon ,
    reef , and shoal in both themes.
    rose is the single accent: primary buttons, links, the active nav underline, list markers, and
   the focus ring. Use one rose-filled button per view, with on-rose text on it.
    seaglass means available or success, amber means limited or warning, coral means
   error. Pair each with a word or an icon, and put it on its -soft ground. Success leans blue-
   green and danger leans orange-red, so they never rely on a red-green distinction.
   Use line for decoration only. The boundary of any control is line-strong (3.4:1 or
   more against every surface).
   The scene-* tokens are for WebGL and the CSS pearl only.
   Never use gradients in interface chrome, purple or blue glows, neon green, or pure black or
   white grounds.
   The dark Lagoon theme is the default and ships at launch. The light Pearl theme is defined
   for P2: it swaps grounds and text and darkens the accent so every pair still clears 4.5:1.

Shape, borders, and elevation
  Radii by role: radius-xs for inline code and keys; radius-sm for inputs, badges, and
  media; radius-md for cards, code blocks, and toasts; radius-lg for the chat panel,
  sheets, and the command palette; radius-pill for anything pressable.
  Borders are 1 px line for decoration and 1.5 px line-strong for controls.
  Elevation comes from the surface step plus shadow-lustre , a one-pixel highlight along
  the top edge. Use shadow-float only for things that float over the page: the chat panel,
  the launcher, toasts, the command palette. There are no other shadows.
  Every interactive element shows shadow-focus on keyboard focus: a 2 px lagoon gap,
  then a solid 2 px rose ring.

Layout
  A 12-column grid inside container-max (1200 px), with a side gutter of max(16px,
  env(safe-area-inset-left)) on phones, 32 px on tablets, and 48 px on desktop.
  Align everything to the left edge of the grid. Nothing is centred except the 404 page.
  Section padding is space-10 on desktop, space-9 on tablets, and space-8 on
  phones. The gap from a section header to its content is space-7 .
  The Layout section has breakpoints and a wireframe of every section.

The pearl, in CSS and in 3D
  In CSS, .kr-pearl paints the pearl from scene-pearl , scene-sheen-rose ,
   scene-sheen-aqua , and a white highlight, at pearl-dot (0.32em) when it replaces a
  full stop.
  In WebGL it is a physical material with iridescence and clearcoat under procedural studio
  light; the Motion and 3D section lists every parameter.
  Use the pearl in exactly four places: the hero (3D), the headline's full stop, the monogram,
  and Pearl (launcher, avatar, typing dots). Nowhere else.

Iconography
  Use Lucide icons (lucide-react) at 20 px with a 1.75 stroke in currentColor , and 16 px
  inside small buttons and toasts.
  No emoji in the interface, the copy, or Pearl's answers.
  Every icon-only button carries an aria-label . The launcher has no icon: the pearl is the
  icon.
  There is no logo file. The monogram is live type: "KR" in Anek Latin 780 at wdth 112, followed
  by the pearl dot.

Imagery
  Show real screenshots and screen recordings of the work at 16:10 on a shoal mat with
   radius-sm . Videos are muted, looped, under 2 MB, with a poster frame.
  No stock photos, no device-frame mockups, no AI-generated illustrations.
  An optional portrait is duotone: lagoon in the shadows, pearl in the highlights.

Content fundamentals
  The site speaks in the first person ("I built…"). Pearl speaks about Kushwant in the third
  person and never pretends to be him.
  Be confident, specific, and warm. Lead with outcomes and numbers, and write numbers in
  digits.
  Use Indian digit grouping for rupees (₹1,50,000) and plain digits elsewhere.

Accessibility
   Meet WCAG 2.2 AA: the contrast pairs above, focus always visible and never hidden under the
   sticky bar, targets of at least 24 px (primary actions target-min , 44 px), and reflow at
   320 px with no horizontal scroll.
   The canvas is aria-hidden and carries no information of its own; everything it shows
   also exists in the HTML.
   Honour prefers-reduced-motion : no opening move, no morphing, no shimmer. The
   3D scene renders one still frame.
   Pearl's log is role="log" with polite announcements, and its confirm card is a real form
   with real buttons.

Components
Each component as it renders in the Lagoon theme, followed by its contract.
Plain-CSS references are in components/bundle.css ; React prop types in

Button
Primary, secondary, quiet, small, busy




Buttons start an action; a rose primary button appears at most once per view, for the thing
that view exists to do.

Variants
   primary: rose fill with an on-rose label. "View my work" in the hero, "Send message" in
   Contact.
   secondary: no fill, 1.5 px line-strong border, pearl label. "Hire me for a project",
   "Résumé".
   quiet: rose text with no box, 44 px tall. Inline actions such as "Ask Pearl about me" and
   "Copy email".
   size sm: 40 px tall with a 14 px label, for the navigation's Résumé button and actions inside
   chat cards.

What the consumer provides
A verb-first label in sentence case (2 to 4 words), an optional 20 px leading icon from lucide-
react, and either href (renders <a> ) or onClick (renders <button
type="button"> ). busy swaps the icon for a spinner and sets aria-busy ; the label
stays so the button doesn't change width.

States
Hover ( rose-hover on primary, shoal on secondary), keyboard focus ( shadow-
focus ), pressed (moves down 1 px), disabled (45% opacity with aria-disabled , so it
stays focusable and the reason sits next to it), busy.

Tailwind recipe
   Base: inline-flex min-h-12 items-center justify-center gap-2
   whitespace-nowrap rounded-pill px-6 text-base font-semibold
   transition-colors focus-visible:outline-none focus-
   visible:shadow-focus active:translate-y-px
   Primary: bg-rose text-on-rose hover:bg-rose-hover
   Secondary: border-[1.5px] border-line-strong text-pearl hover:bg-
   shoal
   Quiet: min-h-11 px-2 text-rose hover:text-rose-hover
   hover:underline underline-offset-4

Do and don't
   Name the result, and keep that name through the flow: "Send message" leads to the toast
   "Message sent".
   Never append arrows ("View work →"), use all caps, or put two primary buttons side by side.
   Never build a button from a div ; icon-only buttons need an aria-label .

Chip
Filter, starter, source




Chips are small pressable pills: project filters, Pearl's starter prompts, and the source links
under Pearl's answers.

Kinds
    filter: toggles a project filter. Renders <button aria-pressed> . Pressed chips use
     rose text and border on rose-soft . Exactly one filter is pressed at a time ("All" by
    default).
    starter: a suggested question in Pearl. Pressing it sends the text as the visitor's message. Up
    to four at once, written as the visitor would ask ("Show me his best project").
    source: a link under a Pearl answer to the section it came from ("Freelance: Clinic booking
    assistant"). 28 px tall, mist text, 1 px line-strong border.

What the consumer provides
The label (sentence case, under 32 characters), plus pressed for filters, onClick for
starters, or href for sources.

Tailwind recipe
    Base: inline-flex min-h-9 items-center gap-2 whitespace-nowrap
    rounded-pill border-[1.5px] border-line-strong px-4 text-sm
    font-medium text-pearl hover:bg-shoal focus-visible:outline-none
    focus-visible:shadow-focus
    Pressed: aria-pressed:border-rose aria-pressed:bg-rose-soft aria-
    pressed:text-rose
    Source: min-h-7 border px-3 text-mist hover:text-pearl

Do and don't
    Chips are pills because they are pressable; read-only labels are Badges.
    Never use chips as a list of skills or tags; use Badge tags or plain text links.
    Keep a filter row to one line on desktop; let it scroll horizontally on phones rather than wrap
    into three rows.

Badge
Status tones and stack tags




Badges are read-only labels for live status and stack tags; they are rounded rectangles
because nothing happens when you press them.

Tones
   available: seaglass on seaglass-soft with a filled dot. "Freelance: 1 slot open in
   November".
   limited: amber on amber-soft with a filled dot. "Freelance: limited until January".
   booked: mist on reef with a hollow dot. "Freelance: booked until March".
   neutral: mist on reef , no dot. Current employer in the hero: "ASE at Knowvation
   Learnings".
   tag: mist text with a 1 px line outline, no fill. Stack names on cards and timeline entries.

What the consumer provides
The words. Status tones always carry a word as well as colour, so they read the same in
greyscale and to screen readers. The freelance status comes from one config value
( availability.freelance ), never hand-typed copy.

   Base: inline-flex min-h-7 items-center gap-1.5 whitespace-nowrap
   rounded-sm px-2.5 text-sm font-medium

   tag: text-mist ring-1 ring-inset ring-line
   Dot: size-2 rounded-full bg-current (booked: ring-[1.5px] ring-inset

Do and don't
   Never make a badge clickable; if it needs to act, it is a Chip.
   Never show more than five tags on a card; the case study lists the full stack.
   Status words are sentence case: "Available", never "AVAILABLE".

NavBar
Over the hero, and after scrolling




The navigation bar is a sticky strip with the KR monogram, five section links, the résumé, and
a way into Pearl.

Anatomy
 1. Monogram: "KR" in Anek Latin 780 at wdth 112, followed by the pearl dot. It links to the top.
    It is live type, not an image, so there is no logo file.
 2. Links: About, Experience, Freelance, Projects, Contact, in ui at weight 560, mist ; hover
    and the section in view turn pearl . The section in view gets aria-
    current="location" and a 2 px rose underline 10 px below the text.
 3. Actions: Résumé (secondary, sm, download icon) and "Ask Pearl" (quiet, with the pearl dot).

Behaviour
   Transparent over the hero. After 80 px of scroll it takes lagoon-veil , a 12 px backdrop
   blur, and a line bottom border. The height never changes, so nothing shifts.
   Sticky at top: env(safe-area-inset-top) , z-nav . Sections set scroll-
   margin-top: var(--nav-height) .
   Below 860 px: monogram, Résumé, and a menu button. The menu opens a full-height sheet

  // scripts/tokens.ts: turns design/tokens.json (exported from the Nacre design system) into src/styles/tokens.css.
  // Run with `node scripts/tokens.ts` (Node 22.18+ runs TypeScript directly) or via `pnpm tokens`.
  import { readFileSync, writeFileSync } from 'node:fs';

  type Value = string | Record<string, string>;
  interface Token { name: string; value: Value; usage?: string }
  interface Family { tokens: Token[] }

  const src = JSON.parse(readFileSync('design/tokens.json', 'utf8'));
  const themes: { id: string }[] = src.color.themes;
  const first = themes[0].id;

  const pick = (t: Token, theme: string): string =>
    typeof t.value === 'string' ? t.value : (t.value[theme] ?? t.value[first]);
  // "{lagoon}" is an alias of another token
  const css = (v: string): string => v.replace(/^\{([A-Za-z0-9_.-]+)\}$/, 'var(--$1)');
  const fam = (key: string): Token[] => ((src[key] as Family | undefined)?.tokens ?? []);

  const colors = fam('color');
  const shadows = fam('shadow');
  const themed = (theme: string, onlyChanged: boolean): string =>
    [
      ...colors.map((t) => [t.name, t] as const),
      ...shadows.map((t) => [`nacre-${t.name}`, t] as const),
    ]
      .filter(([, t]) => !onlyChanged || (typeof t.value !== 'string' && pick(t, theme) !== pick(t, first)))
      .map(([name, t]) => ` --${name}: ${css(pick(t, theme))};`)
      .join('\n');

  const plain = (keys: string[]): string =>
    keys.flatMap(fam).map((t) => ` --${t.name}: ${pick(t, first)};`).join('\n');

  const out = [
    '/* Generated from design/tokens.json by scripts/tokens.ts. Edit the design system, not this file. */',
    '',
    `:root,\n[data-theme="${first}"] {\n color-scheme: ${first};\n${themed(first, false)}\n}`,
    ...themes.slice(1).map((t) => `[data-theme="${t.id}"] {\n color-scheme: ${t.id};\n${themed(t.id, true)}\n}`),
    '',
    `:root {\n${plain(['spacing', 'size', 'zIndex'])}\n}`,
    '',
    '@theme {',
    ' --radius-*: initial;',
    fam('radius').map((t) => ` --${t.name}: ${pick(t, first)};`).join('\n'),
    '}',
    '',
    '@theme inline {',
    colors.map((t) => ` --color-${t.name}: var(--${t.name});`).join('\n'),
    ...shadows.map((t) =>
      t.name === 'shadow-lustre'
        ? ' --inset-shadow-lustre: var(--nacre-shadow-lustre);'
        : ` --${t.name}: var(--nacre-${t.name});`,
    ),
    '}',
    '',
    ...fam('zIndex').map((t) => `@utility ${t.name} {\n z-index: var(--${t.name});\n}`),
    '',
  ].join('\n');
